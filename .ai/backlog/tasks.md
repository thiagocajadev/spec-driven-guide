## Backlog

### Decided against

> Kept so the next reader does not propose them again. The full reasoning is in git history.

- **Warn before overwriting an edited generated file** (won't-do): the kit is out of git and cleared whole on every install, and the off-canon report names what left. A hash ledger plus `.orig` copies would reimplement, worse, what git already does; a 3-way merge leaves conflict markers inside markdown an agent reads as instruction.
- **A `.ai/local/` override layer** (won't-do): an override that wins over the canon is a sanctioned fork that `audit` and `check-sync` cannot see. Per-project customization already lives in `.ai/backlog/`, which the install never overwrites; real divergence is answered by pinning the version or moving the change upstream.
- **Unattended loops as the default** (won't-do, audit 2026-11-18): Ralph loops and `mattpocock/sandcastle` run agents with no human between iterations, which removes the gates the framework exists for. A bounded unattended run shipped in v11.1.0 instead, with a done condition and a human sign-off.
- **A memory server or machine-local memory** (won't-do, audit 2026-11-18): `akitaonrails/ai-memory` and the ECC "instincts" keep the source of truth outside the repository, against the Persistence Policy. Their review rules were taken instead, in v11.1.0: `learned.md` entry rules and the memory precedence.
- **Shipping a sandbox** (won't-do, audit 2026-11-18): `akitaonrails/ai-jail` is accident-grade isolation by its own docs, and it does not run on Windows outside WSL2. Isolation belongs to the harness and the OS.
- **Marketplace distribution as the main channel** (won't-do, audit 2026-11-18): the installer and repository-owned files are the product. Frontmatter, shipped in v11.1.0, keeps the skills readable by marketplace tooling at no cost.
- **Intensity levels and a cost panel** (won't-do, audit 2026-11-18): ponytail's lite/full/ultra modes and token panel are host add-ons outside the kit's scope.
- **Risk-tiered gates** (won't-do, `docs:` 2026-11-18): Anthropic's own code review tiers human approval by risk (claude.dev/blog/solving-code-review-at-anthropic, 2026-10-15, A). Here a gate is a stop before CODE or before a commit, not a queue of human reviewers, so tiering it saves a stop and loses the approval. What the article tiers is already tiered: the SPEC scales with the demand (`workflow.md`, Proportion), and the fresh-context review runs only on an [M] or [L] change or one that touches auth, data or money (`review.md`, Fresh-Context Review).
- **Deferred, not refused** (audit 2026-11-18): behavioral evals that run a headless agent per scenario (superpowers, BMAD), and OpenSpec-style delta specs. Both cost tokens on every run; reopen when a skill regression or a large brownfield project asks for them.
